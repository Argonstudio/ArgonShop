# AI_TESTING.md — как проверять изменения

Продолжение [AI.md](../../AI.md). Какие проверки существуют, что и когда запускать, как менять тесты и как работать без терминала.

## 1. Три уровня проверок

| Уровень | Команда | Нужно | Ловит |
|---|---|---|---|
| **Статическая проверка** | `php tests/static-check.php` | только PHP (без WordPress и базы) | синтаксис, тексты без перевода, неверный text domain, непереведённые строки и сломанные `%s`, несовпадение версий, кириллицу в коде JS/CSS (комментарии RU-ветки на русском и ошибкой не считаются) |
| **Smoke-тест** | `wp eval-file tests/smoke-test.php` | тестовый WordPress + WP-CLI | корзину, цены, обязательные поля, файлы, заказ, письма, регистрацию, кабинет, поиск и раскладки, страницы, админку, валюту, переводы (PHP и JS), ошибки PHP в `debug.log` |
| **Ручной чек-лист** | раздел 6 ниже | браузер | вёрстку, JS, то, что видит человек |

Статическая проверка выполняется за секунды где угодно — **запускайте её всегда**. Smoke-тест — когда есть тестовый сайт (см. `tests/README.md`); запускайте его на каждом языке сайта, который затронули (Настройки → Общие → Язык сайта: English, Русский, Français). Ручной чек-лист — пункты, относящиеся к изменению.

## 2. Режимы работы ИИ

**ИИ с терминалом** (Codex, Claude Code, Cursor и т. п.):

1. До изменения — запустите обе проверки, запомните исходное состояние (если что-то уже красное — сообщите об этом, не исправляйте молча).
2. Изменение.
3. Снова обе проверки. Красное — исправляйте код, а не тест (раздел 4).
4. В ответе: что запускалось и результат (`OK: all 28 checks passed`, `Success: All checks passed: 62`).

**ИИ в чате без терминала** (правит отдельные файлы, тесты запускает пользователь):

1. Не утверждайте «проверено» — вы ничего не запускали.
2. В конце ответа дайте блок «Как проверить»:
   - команду `php tests/static-check.php` (и `wp eval-file tests/smoke-test.php`, если у пользователя есть тестовый сайт);
   - **какие строки вывода важны** для этого изменения — см. таблицу в разделе 3;
   - **2–5 пунктов ручного чек-листа** из раздела 6, относящихся к изменению.
3. Если изменение добавило тексты — таблицу переводов (см. `AI_I18N.md`, раздел 4).
4. Пользователь присылает вывод — строки `✘` показывают, что и где сломалось.

## 4. Правила изменения тестов

- **Тест красный — сначала считайте, что сломан код.** Тест меняется, только если поведение изменено **намеренно** и это сказано в задаче.
- **Запрещено:** ослаблять или удалять проверку, чтобы тест прошёл, — менять ожидаемый итог на «что получилось», убирать проверку nonce, обходить ошибку через `if` в тесте. Это скрывает баг от пользователя.
- Намеренно изменили поведение → исправьте соответствующую проверку **и** напишите в `CHANGELOG.md`, почему.
- Добавили функцию → добавьте проверку:
  - логика PHP/AJAX — в `tests/smoke-test.php`: `as_smoke_check( $condition, 'Что проверяется, простыми словами', $details )`; HTTP-запросы — через `$browser->ajax()` / `$browser->request()` (как браузер, с cookie и nonce); регистрируйте тестовые данные в `$GLOBALS['as_smoke']['cleanup']`, чтобы тест их удалил.
  - правило на уровне кода (новый запрет, новая структура) — в `tests/static-check.php` через `sc_ok()`.
- Подпись проверки — утверждение о правильном поведении («Цена из cookie игнорируется»), а не о коде.
- Тест не должен зависеть от языка сайта: не сравнивайте с переведёнными сообщениями; проверяйте `type`, коды, числа или тексты из собственных тестовых данных либо сравнивайте с `__()` той же строки. Проверки, зависящие от языка, ветвятся по `as_search_language()` / `determine_locale()`.
- Используйте `'cache_results' => false` в `get_posts()`, когда данные созданы HTTP-запросом в другом процессе.
- Тест не должен оставлять мусор или отправлять настоящие письма (временный mu-plugin перехватывает письма).
- Комментарии тестов — на русском, как и остальные комментарии (RU-ветка).

## 5. Что не покрывает автоматизация

Поведение JS в браузере (анимации, переключение вкладок, маски полей), мобильную вёрстку, реальную доставку писем, правило nginx для `argon-shop-private`. Это ручной чек-лист.

## 6. Ручной чек-лист

Откройте сайт в окне инкогнито (чистые cookie). Номера используются в таблице раздела 3.

1. Карточка товара в каталоге → «В корзину»: счётчик и сумма в шапке обновляются без перезагрузки.
2. Страница товара: «+» / «−» меняют количество и сумму; «Купить» ведёт в корзину.
3. Корзина: изменение количества пересчитывает строку, итог и вес; удаление товара; «Очистить корзину».
4. Перезагрузите страницу корзины — содержимое сохраняется.
5. Быстрый заказ с пустыми полями — сообщение о пустых полях, заказ не создаётся.
6. Вкладки «Физические лица» / «Юридические лица» переключаются, поля соответствуют настройкам магазина.
7. Прикрепите 1 изображение и 1 PDF → счётчик «Загружено файлов: 2» на языке сайта, заказ оформлен; прикрепите файл > 5 МБ → понятная ошибка.
8. После заказа: сообщение с номером, корзина пуста, заказ с правильной суммой появился в «Заказах» в админке, письмо пришло.
9. Заказ с галочкой «Зарегистрировать вас?» и email → в письме ссылка для установки пароля (без пароля), пароль можно задать по ссылке.
10. Личный кабинет: изменение и сохранение данных аккаунта.
11. Кабинет → «Заказы»: заказ виден, фильтр по статусу работает.
12. Поиск в шапке: подсказки при вводе; запрос в неверной раскладке находит товары — русский сайт: `njdfh` → «товар»; английский сайт: `ыскуцы` → «screws» (набрано в русской раскладке); французский сайт: `срйшыу` / `chqise` → «chaise».
13. Главная, каталог, товар, корзина, кабинет, 404 открываются, вёрстка не сломана (в том числе при ширине 375 px).
14. В консоли браузера (F12) нет красных ошибок на этих страницах.
15. Админка: редактирование товара (цена, галерея, характеристики) и заказа (добавить товар, пересчитать) сохраняется.
16. «Настройки → Общие → Язык сайта» = Français / English: витрина и админка магазина на выбранном языке, включая сообщения JS (корзина, поиск, модальное окно) — нет русского текста; переключите обратно на русский — всё как раньше.
17. «Настройки → Магазин → Валюта»: USD → `$120` везде (карточки, страница товара, корзина, шапка, письма); EUR → `120 €`; RUB → `120 Р` на русском сайте.

## Регрессионные проверки чисел, оптовых ступеней и паролей

```bash
php tests/static-check.php
php tests/regression-check.php
node tests/number-check.mjs
wp eval-file tests/smoke-test.php
```

Секция 7 static-check проверяет токены кода (игнорируя пробелы/комментарии) и запускает изолированный PHP-набор. `regression-check.php` загружает реальные функции цен/кабинета с заглушками WordPress; он **не** проверяет реальное хеширование WordPress, cookie, HTTP, БД и хуки. PHP- и JS-наборы читают общие числовые фикстуры. Node нужен только для JS-проверки, а не для PHP static-check.

Секция 12 smoke-теста проверяет реальный WordPress: цены/термины с запятой, суммы ниже и ровно на пороге, оба порядка ступеней, отключённые скидки, замену цены cookie и AJAX-итог; пароли с `%xx`, тегами, повторяющимися пробелами, кавычками/слешами, текущий «0», короткий новый «0», длину UTF-8 и несовпадение подтверждения. Созданные термины/товары/пользователи удаляются; существующие термины используются без удаления. Запускайте smoke только на тестовом сайте. Успех изолированных проверок не заменяет smoke.

Эта сборка имеет номер 1.1.0. Версионированные URL CSS/JS изменяются; при выкладке очистите кэш CDN или страниц, если он продолжает отдавать старые ресурсы.
