# POSITIONING.md — когда использовать ArgonShop, а когда нет

Этот документ описывает нишу, для которой создан ArgonShop. Он предназначен
для разработчиков, заказчиков и ИИ-ассистентов, которые оценивают, подходит ли
этот стек для конкретного проекта.

> **Коротко:** ArgonShop — правильный выбор для **нестандартных
> интернет-магазинов на заказ**, где важны уникальность и полное владение кодом.
> Для **типовых магазинов «из коробки»** обычно лучше подойдёт WooCommerce
> или аналогичная платформа.

---
## 1. Что такое ArgonShop

ArgonShop — **лёгкий самодостаточный стек интернет-магазина** для WordPress: плагин (бизнес-логика) плюс тема (разметка и стили). Это современный монорепозиторий на **Vanilla JS и нативных ES-модулях — полностью без сборщиков, этапов сборки и привязки к фреймворкам**. Вся кодовая база намеренно спроектирована так, чтобы быть **читаемой, расширяемой и понятной для ИИ**.

Это не конкурент WooCommerce по количеству функций. Это **основа для магазинов
на заказ**, где WooCommerce будет мешать.

---

## 2. Когда ArgonShop — правильный выбор

Выбирайте ArgonShop, если верно большинство из следующего:

- **Магазин нестандартный.** Необычная логика цен, B2B-уровни, своя
  структура каталога, нишевые типы товаров или бизнес-правила, которые
  плохо ложатся на WooCommerce.
- **Уникальность важнее функций.** Заказчик платит за магазин, который делает
  то, чего не делают другие, — а не за копию шаблона.
- **Важно полное владение кодом.** Вы хотите владеть стеком, а не арендовать
  его у вендора, чьи обновления могут сломать ваши доработки.
- **Ожидается долгосрочная поддержка.** Собственную кодовую базу проще
  сопровождать годами, чем сильно доработанную платформу, которую вы не контролируете.
- **Команда маленькая.** Один разработчик плюс ИИ-ассистенты могут вести
  весь проект. Не нужно нанимать «сеньора по WooCommerce» для изменений.
- **Хостинг и обновления под вашим контролем.** Никаких сторонних циклов
  обновлений, диктующих ваш план развития.
- **Разработка с помощью ИИ — часть рабочего процесса.** ArgonShop изначально
  спроектирован для этого (см. раздел 4).

**Типичные примеры:**

- B2B-магазины с оптовыми ступенями цен.
- Нишевые каталоги с нетривиальной фильтрацией или перекрёстными связями.
- Магазины, где оформление заказа должно следовать определённому бизнес-процессу.
- Портфолио и демо-проекты, которые должны показать чистую архитектуру.
- Клиентские проекты, где магазин — часть большого сайта на заказ.

## 3. Когда лучше WooCommerce (или другая платформа)

Будьте честны с собой. Выбирайте зрелую платформу, если верно большинство из следующего:

- **Магазин типовой.** Каталог, корзина, оформление, оплата, доставка —
  ничего экзотического.
- **Скорость запуска важнее уникальности.** Две недели, а не два месяца.
- **Заказчик будет управлять магазином сам.** Ему нужна привычная админка,
  и он ожидает «как принято в WordPress».
- **Нужна интеграция с конкретными сервисами.** Если готовый плагин для
  платёжного шлюза, службы доставки или налогового сервиса уже есть, писать
  собственную интеграцию — потраченные впустую усилия.
- **Проект будет передан** другой команде, которая будет ожидать
  известную платформу.
- **Важны пограничные случаи, и вы не можете позволить себе находить их сами.**
  WooCommerce проверен на миллионах магазинов. Закрытые в нём гонки,
  правила округления валют и тонкости оформления заказа дорого
  воспроизводить с нуля.

**Типичные примеры:**

- Стандартный интернет-магазин для малого бизнеса.
- Магазин, где заказчик хочет «WooCommerce, но со своей темой».
- Проекты, которым нужны Stripe/PayPal/ещё 10 шлюзов «из коробки».

## 4. Почему ArgonShop хорошо работает с ИИ-ассистентами

Это осознанная цель проектирования, а не случайность. У проекта есть свойства,
которых нет и не может быть у большинства платформ, включая WooCommerce:

| Свойство | Почему это важно для ИИ |
|---|---|
| **Нет раздутой БД и легаси** | Схема БД минимальна. ИИ не нужно разбираться в многолетних обходных решениях WooCommerce в postmeta. |
| **Vanilla JS, без фреймворка** | Никакой скрытой магии, нечего объяснять про сборку, нет расхождения версий фреймворка. |
| **Небольшая кодовая база** | Весь проект помещается в контекстное окно LLM. ИИ видит полную картину. |
| **Явные контракты** | DOM-селекторы, AJAX-действия, мета-ключи и форматы cookie задокументированы. ИИ не гадает. |
| **Жёсткие запреты** | Правила «не делай X» работают в промптах лучше, чем описания «делай Y». |
| **Слоистая архитектура** | ИИ знает, куда класть новый код: логика в плагине, разметка в теме. |
| **Без сборщика** | ES-модули загружаются напрямую. Нечего компилировать, нечего неправильно настроить. |
| **Отдельная документация для ИИ** | `AI.md` и связанные файлы дают ассистентам надёжный контекст с первого запроса. |

Сравните с WooCommerce:

- **Огромная кодовая база** — ИИ видит только фрагмент за раз.
- **Неявные соглашения** — тысячи хуков, фильтров и побочных эффектов,
  которые модели приходится восстанавливать по неполным знаниям.
- **Привязка к фреймворкам** — jQuery, Backbone, React-админка, REST API — много
  слоёв, о которых нужно рассуждать одновременно.
- **Частые несовместимые изменения** — совет, который ИИ даёт сегодня, может
  оказаться неверным после следующего мажорного релиза.

Вывод простой: **чем уникальнее магазин, тем больше преимущество маленького,
понятного ИИ стека перед большой универсальной платформой.**

## 5. Чем ArgonShop не является

Чтобы правильно настроить ожидания:

- **Не готовая замена WooCommerce.** Другой масштаб,
  другие цели.
- **Не платформа маркетплейса.** Логики нескольких продавцов «из коробки» нет.
- **Не SaaS.** Только на собственном хостинге.
- **Не полнофункциональное решение.** Базовые действия корзины и каталога есть, но оплата, доставка, сложные налоги
  и расширенная отчётность создаются или интегрируются под каждый проект, а не поставляются по умолчанию.
- **Не для «хочу, чтобы было как в WooCommerce».** Если цель такая,
  используйте WooCommerce.

---

## 6. Чек-лист для принятия решения

Ответьте на эти вопросы. Чем больше ответов «да», тем больше подходит ArgonShop;
чем больше «нет» — тем больше подходит WooCommerce или другая платформа.

1. Есть ли у магазина нестандартная бизнес-логика?
2. Платит ли заказчик за уникальность, а не за шаблон?
3. Контролируете ли вы хостинг и цикл обновлений?
4. Будет ли проект долго сопровождаться небольшой командой?
5. Входит ли разработка с помощью ИИ в ваш рабочий процесс?
6. Готовы ли вы сами делать интеграции (оплата, доставка)?
7. Допустима ли (или даже желательна) собственная админка?
8. Должна ли кодовая база оставаться в вашей собственности?

**8 «да»** → ArgonShop почти наверняка правильный выбор.
**4–7 «да»** → ArgonShop подойдёт, но заложите дополнительное время на интеграции.
**0–3 «да»** → Используйте WooCommerce, Shopify или другую зрелую платформу.

---

## 7. Итог

> ArgonShop + ИИ = **быстрая разработка уникальных магазинов** с полным контролем.
> WooCommerce + ИИ = **быстрый запуск типовых магазинов** с ограничениями.

Эти два подхода не конкурируют напрямую. Они обслуживают разные
сегменты. ArgonShop сильнее всего там, где WooCommerce слабее всего:
B2B, нестандартные каталоги, нишевая логика и проекты с
долгим горизонтом поддержки.
