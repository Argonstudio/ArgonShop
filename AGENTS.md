# AGENTS.md

> Полный контекст проекта для ИИ-ассистентов — в [`AI.md`](AI.md) и связанных документах ([`docs/ai/`](docs/ai/)). Ветка `ru`: документация и комментарии в коде на русском.

## Зачем этот файл

Разные ИИ-ассистенты ищут файлы контекста с разными именами:
| Инструмент | Что читает автоматически | В этом репозитории |
|------------|---------------|--------------------|
| OpenAI Codex | `AGENTS.md` | ✅ этот файл |
| Cursor | `AGENTS.md`, `.cursor/rules/` (устар.: `.cursorrules`) | ✅ `AGENTS.md` |
| Claude Code | `CLAUDE.md` | ✅ `CLAUDE.md` — подгружает `AGENTS.md` и `AI.md`; `.claude/` — команды `/check`, `/new-ajax` и хук static-check |
| Aider | ничего по умолчанию | ⚠️ запустите `aider --read AI.md` (или укажите его в `read:` в `.aider.conf.yml`) |
| Windsurf и другие | свои файлы правил | ⚠️ приложите `AI.md` к контексту вручную |

`AI.md` сам не читает ни один инструмент — это общий указатель, на который ведут ссылки.
Чтобы избежать дублирования, **весь контекст находится в `AI.md` и `docs/ai/AI_*.md`**.
Английская версия плагина и документации — основная ветка `main` репозитория на GitHub; эта ветка `ru` — русская.
Этот файл — короткий указатель.

> **Claude Code** читает `CLAUDE.md`, а через него — `AGENTS.md` и `AI.md` (импорт `@`). Остальные файлы `docs/ai/` читайте по задаче.

## Порядок чтения

1. **`AI.md`** — указатель, ключевые контракты, жёсткие запреты.
2. **`docs/ai/AI_ARCHITECTURE.md`** — слои, модули, карта папок.
3. **`docs/ai/AI_DATA_FLOWS.md`** — сценарии работы с данными.
4. **`docs/ai/AI_AJAX_REFERENCE.md`** — AJAX-действия.
5. **`docs/ai/AI_TEMPLATE_MAP.md`** — шаблоны темы.
6. **`docs/ai/AI_EXTENDING.md`** — как добавлять функции (в т. ч. выбор города — раздел 13).
7. **`docs/ai/AI_FUNCTION_NAMES.md`** — старые → новые имена функций (1.1.0).
8. **`CHANGELOG.md`** — что изменилось между версиями.
9. **`docs/ai/AI_TESTING.md`**, **`AI_VERSIONING.md`**, **`AI_I18N.md`** — проверки, версии, переводы.

> Если задача — правка в конкретной области, читайте только `AI.md` + соответствующий специализированный файл. Если задача затрагивает архитектурные принципы, требует крупного рефакторинга или выбора между альтернативными подходами, дополнительно прочитайте [`docs/ai/AI_DESIGN_RATIONALE.md`](docs/ai/AI_DESIGN_RATIONALE.md). Не загружайте этот документ для каждой небольшой правки.

## Короткие правила

- **jQuery на фронтенде запрещён.** Только Vanilla JS и ES-модули.
- **Не меняйте DOM-селекторы и AJAX-действия** без синхронной правки PHP и JS.
- **Не меняйте формат мета-полей и cookie** — в них уже есть данные.
- **Разделение слоёв:** логика в плагине, разметка в теме.
- **Цены только из БД** (`as_get_product_price()`), обязательные поля только на сервере (`as_get_required_fields()`), nonce в каждом AJAX-действии.
- **Новые функции получают префикс `as_`**; переименование публичной функции требует обёртки в `includes/legacy-functions.php`.
- **Все видимые пользователю тексты — на английском внутри `__()` / `esc_html_e()`** с доменом `argon-shop` (плагин) или `argon-shop-theme` (тема); обновляйте переводы (`AI_I18N.md`).
- **Текст в JS только через `t()`** из `core/config.js`; **цены только через хелперы валюты** (`as_price_html()`, `astheme_price_html()`); **комментарии в коде — на русском (RU-ветка)**: `static-check` (проверка 6) разрешает кириллицу в комментариях PHP и JS/CSS и падает только на кириллице в коде JS/CSS вне комментариев; изменения контрактов отражайте в `docs/ai/` (и сообщите пользователю, что их нужно перенести в английскую ветку `main`).
- **Версии:** никогда не добавляйте `@version` в файлы; каждая правка → строка в `CHANGELOG.md` `[Unreleased]`; повышайте версию только при релизе (`AI_VERSIONING.md`).
- **Проверяйте изменение:** `php tests/static-check.php` всегда, `wp eval-file tests/smoke-test.php` на тестовом сайте. Нет терминала — скажите пользователю, что запустить и на что смотреть (`AI_TESTING.md`). Никогда не ослабляйте тест, чтобы он прошёл.

Над набором документации для ИИ (`AI.md`, `docs/ai/AI_*.md`, этот файл и их английские версии в ветке `main`) работали:

Рамки, цели и критерии приёмки определил мейнтейнер; формулировки и структуру подготовили модели; каждый контракт и запрет отражает решения мейнтейнера и состояние репозитория на момент написания.
